# Docker Plan de Implementación

> **Para trabajadores agénticos:** SUB-HABILIDAD REQUERIDA: Usa superpowers:subagent-driven-development (recomendado) o superpowers:executing-plans para implementar este plan tarea por tarea. Los pasos usan casillas de verificación (`- [ ]`) para el seguimiento.

**Objetivo:** Correr fcmanager en el PC casero con Linux Mint (`coshinema`) dentro de un contenedor Docker que arranca solo al prender el equipo y se abre desde cualquier dispositivo de la casa en el puerto 2300, sin levantar `bin/dev`.

**Arquitectura:** Un `Dockerfile` en dos etapas: la etapa `build` instala las gemas, toma Node 22 de `node:22-slim` y compila los assets con esbuild, y la imagen final solo lleva Ruby, las gemas, `sqlite3` y la app ya compilada, corriendo en `HANAMI_ENV=production`. `bin/docker-entrypoint` corre `hanami db prepare` (crea la base si falta, migra y carga los seeds idempotentes) y luego arranca puma. `compose.yml` publica el 2300, monta `./db` del repo como volumen para usar la base que ya existe en `coshinema`, y tiene `restart: unless-stopped` para que el contenedor vuelva después de cada reinicio.

**Stack Tecnológico:** Docker Engine + Docker Compose v2, `ruby:3.4.8-slim` (Debian), Bundler 4.1.0, Node 22 (solo para compilar), Hanami 3.0.2, puma 8, SQLite.

**Especificación:** Reporte de revisión del 2026-11-26 (conversación con el usuario). Decisiones del usuario:

1. **Puerto 2300**, el mismo de siempre. En `coshinema` se deja de usar `bin/dev`.
2. **Los datos buenos** son los de `db/fcmanager.sqlite` en `coshinema`, no los del Mac.
3. **`coshinema` es x86_64** (64 bits).

**Prueba previa (2026-11-26):** el `Dockerfile`, el entrypoint y el `.dockerignore` de la Tarea 1.1 se construyeron con `--platform linux/amd64` desde una copia del repo. Funcionaron así: base vacía → se crea, migra y carga seeds; copia de una base con 28 jugadores → los 28 siguen ahí; `/`, `/formation` y el CSS responden 200 (`text/css`); `POST /formation/clear` escribe en el archivo del host; los datos sobreviven a `docker restart`. La imagen pesa ~213 MB.

## Restricciones Globales

- Ruby `3.4.8` (`.ruby-version`, `mise.toml`) y Bundler `4.1.0` (`BUNDLED WITH` en `Gemfile.lock`). La imagen base trae Bundler 2.x: hay que instalar el 4.1.0 con `gem install bundler -v 4.1.0`.
- El paquete npm `hanami-assets` exige **node >= 22**. El Node de Debian (18) no sirve: copiarlo desde `node:22-slim`, y solo en la etapa `build`.
- `HANAMI_ENV=production` apaga el servido de assets (`hanami/config/assets.rb:61`). Es obligatorio `HANAMI_SERVE_ASSETS=true`.
- `dotenv` solo está en los grupos development/test: en producción **no** se lee `.env`. `DATABASE_URL=sqlite://db/fcmanager.sqlite` va como `ENV` en la imagen.
- `hanami db prepare` usa el programa `sqlite3` de línea de comandos (carga y vuelca `config/db/structure.sql`), así que el paquete apt `sqlite3` va en la imagen final.
- `BUNDLE_WITHOUT=development:test`. **No** excluir el grupo `cli`: ahí está `hanami-reloader`, que la CLI de Hanami espera.
- Puerto del contenedor y del host: **2300** (`config/puma.rb` ya escucha en `0.0.0.0`). Para pruebas en el Mac usar otro puerto del host (por ejemplo `-p 2399:2300`), nunca el 2300.
- El usuario del contenedor es `app` con **uid 1000**; tiene que coincidir con el dueño de `db/` en `coshinema`.
- No se toca código de la app, ni `bin/dev`, ni `Procfile.dev`: en el Mac se sigue desarrollando igual.

## Enfoque de Revisión

1. **El contenedor arranca con la base existente de `coshinema`** → no se pierde ni se reinicia nada: el número de `players` es el mismo antes y después. Prueba: Tarea 2.1, pasos 1 y 5.
2. **`bin/dev`/foreman sigue corriendo o se lanza solo al prender** → `docker compose up` falla con "port is already allocated", o dos procesos escriben en el mismo SQLite. Se apaga y se revisa que nada lo lance al arrancar. Prueba: Tarea 2.1, paso 2.
3. **Se reinicia el PC** → el contenedor vuelve solo y la app responde sin que nadie entre a la máquina. Prueba: Tarea 2.1, paso 7.
4. **El dueño de `db/` no tiene uid 1000** → SQLite responde "attempt to write a readonly database" al guardar. Se revisa con `stat` y se corrige con `chown`. Prueba: Tarea 2.1, paso 3.
5. **Página sin estilos en producción** (falta `HANAMI_SERVE_ASSETS`) → el CSS debe responder 200 `text/css`. Prueba: Tarea 1.1, paso 6, y Tarea 2.1, paso 5.

- [ ] **Paso 1: `Dockerfile`**

```dockerfile
# syntax=docker/dockerfile:1

# Debe coincidir con .ruby-version / mise.toml
ARG RUBY_VERSION=3.4.8
FROM ruby:${RUBY_VERSION}-slim AS base

WORKDIR /app

ENV HANAMI_ENV=production \
    BUNDLE_DEPLOYMENT=1 \
    BUNDLE_PATH=/usr/local/bundle \
    BUNDLE_WITHOUT=development:test \
    DATABASE_URL=sqlite://db/fcmanager.sqlite \
    HANAMI_SERVE_ASSETS=true

# Debe coincidir con BUNDLED WITH de Gemfile.lock
RUN gem install bundler -v 4.1.0


# Etapa de construcción: gemas nativas + assets (Node solo vive aquí)
FROM base AS build

RUN apt-get update -qq && \
    apt-get install -y --no-install-recommends build-essential

# hanami-assets (npm) exige node >= 22
COPY --from=node:22-slim /usr/local/bin/node /usr/local/bin/node
COPY --from=node:22-slim /usr/local/lib/node_modules /usr/local/lib/node_modules
RUN ln -s ../lib/node_modules/npm/bin/npm-cli.js /usr/local/bin/npm

COPY Gemfile Gemfile.lock ./
RUN bundle install && \
    rm -rf "${BUNDLE_PATH}"/ruby/*/cache

COPY package.json package-lock.json ./
RUN npm ci

COPY . .
RUN bundle exec hanami assets compile && \
    rm -rf node_modules


# Imagen final
FROM base

# hanami db prepare usa la CLI sqlite3 para cargar/volcar structure.sql
RUN apt-get update -qq && \
    apt-get install -y --no-install-recommends sqlite3 && \
    rm -rf /var/lib/apt/lists/*

# uid 1000 = primer usuario de Linux Mint, dueño de ./db en el host
RUN useradd --create-home --uid 1000 app

COPY --from=build /usr/local/bundle /usr/local/bundle
COPY --from=build --chown=app:app /app /app

USER app

EXPOSE 2300

ENTRYPOINT ["bin/docker-entrypoint"]
CMD ["bundle", "exec", "puma", "-C", "config/puma.rb"]
```

```sh

```

```bash

```

Verificar que git guarde el bit de ejecución: `git ls-files -s bin/docker-entrypoint` debe empezar con `100755` después del `git add`.

- [ ] **Paso 4: `compose.yml`**

```yaml
services:
  web:
    build: .
    image: fcmanager
    container_name: fcmanager
    restart: unless-stopped
    ports:
      - "2300:2300"
    volumes:
      # La base vive en el host (db/ del repo, ignorada por git).
      - ./db:/app/db
```

- [ ] **Paso 5: Documentación**

En `README.md`, al final:

```markdown
## Correr en casa con Docker

En el PC que sirve la app (Linux, con Docker Engine y el plugin compose):

- Primera vez o después de actualizar: `git pull && docker compose up -d --build`
- Abrir desde cualquier dispositivo de la casa: `http://<ip-del-pc>:2300`
- Logs: `docker compose logs -f`
- Detener: `docker compose down`

La base es `db/fcmanager.sqlite` del host (montada como volumen). Las migraciones
y seeds corren solos al arrancar el contenedor. Para un backup basta copiar ese archivo.

No correr `bin/dev` en ese PC mientras el contenedor esté arriba: usan el mismo
puerto y la misma base.
```

En `AGENTS.md`, dentro de `## Commands`, después de la línea de `Asset build (prod)`:

```markdown
- Docker (prod, PC casero): `docker compose up -d --build` → puerto 2300, base en `./db` montada. Para probar en el Mac usar otro puerto: `docker build -t fcmanager . && docker run --rm -p 2399:2300 -v "$PWD/tmp/docker-db:/app/db" fcmanager`
```

### Tarea 1.2: Instalar Docker en `coshinema` (manual, sin PR)

Se hace en el PC Linux Mint. No depende de la Tarea 1.1.

- [ ] **Paso 1: Repositorio oficial de Docker** (Mint usa el codename de Ubuntu de su base, que viene en `UBUNTU_CODENAME`)

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$UBUNTU_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
```

- [ ] **Paso 2: Instalar Engine + compose**

```bash
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

- [ ] **Paso 3: Arranque automático y usuario sin sudo**

```bash
sudo systemctl enable --now docker containerd
sudo usermod -aG docker "$USER"
# cerrar sesión y volver a entrar para que tome el grupo
```

- [ ] **Paso 4: Verificar**

```bash
systemctl is-enabled docker          # enabled
docker run --rm hello-world          # "Hello from Docker!" sin sudo
docker compose version               # Docker Compose version v2.x
uname -m                             # x86_64
id -u                                # 1000 (si no, ver Tarea 2.1 paso 3)
```

- [ ] **Paso 2: Apagar `bin/dev` y asegurarse de que no se lance solo**

```bash
crontab -l 2>/dev/null | grep -i -e fcmanager -e foreman -e bin/dev
systemctl --user list-unit-files | grep -i -e fcmanager -e foreman
```

Si aparece algo en crontab, systemd o autostart, quitarlo.

- [ ] **Paso 3: Permisos de `db/`**


Si no son 1000: `sudo chown -R 1000:1000 db`.

